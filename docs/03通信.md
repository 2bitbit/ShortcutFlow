## 1. 数据的传输
### 1.1 数据的流向
数据被打包为 `DataEnvelope` 结构体，按引擎 -> 节点 -> 引擎 -> 节点 -> 引擎 -> 节点 -> ... 的过程不断传输。

> [!WARNING] Shell 组件有 **60 秒硬超时**（`shell.rs:53`）。超时后进程被强制中止，流执行报错。如果自定义组件需要更长执行时间，请在脚本内部自行拆分或异步处理。

### 1.2 自定义组件的实现（内置组件--shell组件的原理）
自定义组件本质上是内置组件`shell`的一个面向UI的友好化封装。

你的自定义组件要严格处理：
  - `stdin`: 引擎将 `DataEnvelope` 序列化后送入自定义组件的 `stdin`。

  - `stdout`: 引擎接收数据后，检查退出码。如果是 0 : 读取 `stdout`，尝试反序列化为结构体 `DataEnvelope` 后传递。
    - 所以你的 `stdout` 输出的字符串必须要能按 JSON 格式反序列化为`DataEnvelope`结构体
    - 注意： 如果你没在终端输出任何东西， 则构造默认的`DataEnvelope`结构体，其`metadata`和`payload`为 null）

  - `stderr`: 引擎接收数据后，检查退出码。如果为非零值（进程失败）：熔断流的执行，记录日志，弹出报错弹窗，内容为 `stderr`。

## 2. DataEnvelope结构体
```json
{
  "metadata":<具体的内容由组件作者自己说明>,
  "payload":<具体的内容由组件作者自己说明>
}
```

DataEnvelope是一次性的，输入节点后就全权交给节点自己处理了。
备注：
  - 没有`Option<DataEnvelope>`一说，强制要求按上述格式输出，不然直接流执行报错！
    - 好处：绝对的显式、可控。


## 3. 关于Shell组件的特殊处理
内置的Shell组件比较特殊，担任着自定义组件背后的核心。

如果你输出纯字符串，这会自动在底层回退为：
```json
{
  "metadata": null,
  "payload": "你输出的字符串"
}
```

如果你输出为空，这会自动在底层回退为：
```json
{
  "metadata": null,
  "payload": null
}
```

## 4. 关于metadata和流编辑页面的配置
`metadata`：由节点传出后，引擎会将下一个节点的节点配置与`metadata`合并，然后再执行下一个节点的逻辑。
备注：
  - 合并期间，发现冲突，就直接报错。
