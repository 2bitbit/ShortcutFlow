# ShortcutFlow 数据流转说明

本文档描述数据在 ShortcutFlow 引擎中如何从上游节点流向组件，以及配置合并与自动解析机制。

---

## 1. 数据结构：DataEnvelope

节点之间通过 `DataEnvelope` 传递数据：

```json
{
  "metadata": { "key": "value", ... },   // JSON 对象，参与配置合并
  "payload":  "数据内容"                   // 任意 JSON 值，不参与合并
}
```

- **metadata**：由上一个节点输出，引擎会将其合并进下一个节点的配置中。用于传递控制信号（如 KeyListener 的按键选择、Router 的匹配结果）。
- **payload**：主要数据内容，组件自行读取使用。不会自动合并到配置中。

---

## 2. 配置合并（引擎层）

每个节点执行前，引擎按**三层优先级**合并配置：

```
comp.default_config          ← 最低（组件 JSON 定义的默认值）
  → 被 node.config 覆盖      ← 中（用户在流编辑器中对该节点的配置）
  → 被 metadata 覆盖          ← 高（上游节点传来的元数据）
```

**冲突熔断**：如果 metadata 中出现了 `node.config`（用户在流编辑器中显式设置）已存在的键，引擎会报错中断流执行并弹出错误对话框。注意：metadata 覆盖 `default_config`（组件默认值）是**合法且预期的**——默认值本就被设计为可被上层覆盖，不会触发冲突。

伪代码：
```
node_keys = node.config.keys()   // 只记录用户显式设置的键
merged = {}
merged.insert_all(default_config)
merged.insert_all(node.config)
for k, v in metadata:
    if k in node_keys: error!    // 仅与用户显式设置冲突
    merged[k] = v                // 覆盖 default_config → 正常
```

## 3. JSON 自动解析

### 3.1 为什么需要

部分组件（KeyListener、Router、EmitData）的配置字段在 UI 中通过 textarea 输入。这些字段的内容是 JSON 结构（数组或对象），但**在组件 JSON 定义的 `default_config` 中，它们被预先存储为 JSON 字符串**：

```json
// KeyListener.json 的 default_config
"keys": "[{\"key\":\"Alt+F1\",\"metadata\":{},\"payload\":\"选项一\"}]"
//        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//        这是一个 JSON 字符串，不是原生数组

// Router.json 的 default_config
"rules": "[{\"condition\":{\"type\":\"char_count_gt\",\"value\":10},\"subflow_id\":\"...\"}]"
//         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//         同样是 JSON 字符串
```

这样做是因为 `default_config` 会被原样复制到 `node.config`，然后传给 Vue 前端。Vue 的 textarea `v-model` 绑定的值必须是字符串——如果绑定原生数组/对象，Vue 会调用 `.toString()`，显示 `[object Object]`。所以在数据源头就存储为字符串，Vue 只是原样显示和回传，不存在「Vue 序列化」这一步。

### 3.2 完整链路

```
组件 JSON 的 default_config
  keys: "[{\"key\":\"F5\"}]"          ← 已经是 JSON 字符串（源头的选择）
    ↓ serde 反序列化
  Rust: String("[{\"key\":\"F5\"}]")
    ↓ Tauri IPC (JSON)
  Vue: comp.config.keys = '[{"key":"F5"}]'   ← JS 字符串，不是数组
    ↓ textarea v-model（直接绑定字符串）
  用户编辑 "[{\"key\":\"F6\"}]"
    ↓ 保存流（JSON.stringify）
  流 JSON 文件: "keys": "[{\"key\":\"F6\"}]"   ← 字符串持久化
    ↓ 引擎加载 → 配置合并 → 自动解析
  组件收到的 ctx.input_data.metadata
    keys: [{"key": "F6"}]             ← 已解析为原生数组
```

### 3.3 引擎实现

引擎在配置合并完成后、传递给组件之前，遍历合并结果的所有字段：

```rust
for (_, v) in merged_config.iter_mut() {
    if let Some(s) = v.as_str() {
        let trimmed = s.trim();
        if trimmed.starts_with('{') || trimmed.starts_with('[') {
            if let Ok(parsed) = serde_json::from_str::<Value>(trimmed) {
                *v = parsed;  // 成功 → 替换为解析后的 JSON 值
            }
            // 失败 → 保留原字符串（可能是合法的以 { 或 [ 开头的非 JSON 文本）
        }
    }
}
```

**关键点**：
- 只对字符串类型的值尝试解析。如果值已经是原生 JSON 数组/对象（例如用户手动编辑流 JSON 文件），`v.as_str()` 返回 None，直接跳过——原生值原样保留。
- 解析失败回退为字符串，避免误伤合法文本（如 html_content 的内容碰巧以 `{` 开头）。
- 这取代了之前在 KeyListener、Router、EmitData 中各自写的 `as_array()` + `as_str()` 双路径解析——组件现在直接按原生类型读取即可。

---

## 4. 组件内部数据流向

```
引擎传入 ctx.input_data { metadata, payload }
  ↓
组件读取 ctx.input_data.metadata   →  组件配置（已合并 + 已解析）
组件读取 ctx.input_data.payload    →  上游数据内容
  ↓
组件执行业务逻辑
  ↓
组件返回 DataEnvelope { metadata, payload }
  ↓
引擎将此 DataEnvelope 作为下一个节点的 input_data
```

## 5. 图文总结

```
┌─────────────────────────────────────────────────────────┐
│ 引擎循环                                                 │
│                                                          │
│  节点 N 的 DataEnvelope                                  │
│    │                                                     │
│    ├─→ metadata ──→ 合并进 节点 N+1 的配置               │
│    │     default_config + node.config + metadata          │
│    │     → 自动解析 JSON 字符串                          │
│    │     → 传给组件                                      │
│    │                                                     │
│    └─→ payload ──→ 传给节点 N+1（组件按需读取）           │
│                                                          │
│  节点 N+1 执行业务逻辑 → 返回 DataEnvelope → 循环          │
└─────────────────────────────────────────────────────────┘
```
